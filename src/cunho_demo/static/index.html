      How it works

      1. 1OfferThe page asks the issuer for a credential offer for a fictional person and shows it as a QR code.ChoosePick an identity card or a course certificate, for a fictional person.
      2. 2TokenYour wallet reads the offer and the issuer's metadata, and gets an access token bound to a key only it holds (DPoP).RequestA wallet asks the issuer for it, with a key that only the wallet holds.
      3. 3ProofThe wallet proves it holds the key the credential will be bound to, and asks for the credential.SignThe issuer checks the wallet, then signs the credential so that nobody can change it.
      4. 4SignatureThe issuer signs it, gives it a place on its status list, and logs the issuance without the person's data.StoreThe credential goes into the wallet. Here, a demo wallet this page runs for you.
      5. 5ConfirmationThe wallet tells the issuer it stored the credential. This page has followed each step through the issuer's operator API.CheckAnyone can check that it is genuine, and the issuer can revoke it at any time.
      Wallets

      It works with wallets that follow OpenID4VCI 1.0 and HAIP.

      Privacy

      No cookies, no analytics, nothing loaded from other sites. A session lives 30 minutes in memory and holds no personal data: the people are fictional.

      Open source

      The issuer is cunho, open source under the AGPL-3.0, built from the EU rules up.
