# Protocol checklist for an EUDI credential issuer

The protocol specifications, and the sections of each, that the binder's spec rows are taken from (`binder/src/rows_spec.py`).

- OpenID4VCI 1.0 Final (16 Sep 2025): https://openid.net/specs/openid-4-verifiable-credential-issuance-1_0.html
  Key sections: 4.1.1 offer + pre-authorized_code + tx_code; 5 authorization (PKCE, PAR recommended); 6.1/6.3 token request + tx_code errors (invalid_request vs invalid_grant); 7 nonce endpoint (7.2 Cache-Control no-store); 8.2 credential request (credential_identifier XOR credential_configuration_id; `proofs` only, singular `proof` is gone); 8.3 response (200 / 202 deferred, credentials array, notification_id); 8.3.1.2 error codes (invalid_credential_request, unknown_credential_configuration, unknown_credential_identifier, invalid_proof, invalid_nonce, invalid_encryption_parameters, credential_request_denied); 9 deferred (invalid_transaction_id); 11 notification (events credential_accepted/failure/deleted, 204, invalid_notification_id); 12.2.2 well-known path insertion; 12.2.4 metadata fields, batch_credential_issuance.batch_size >= 2, key_attestations_required; App. A.2 mso_mdoc, A.3 dc+sd-jwt; App. D key attestation (typ key-attestation+jwt, attested_keys, exp required with jwt proof); App. F.1 jwt proof (typ openid4vci-proof+jwt, alg not none/symmetric, kid/jwk/x5c mutually exclusive, aud = issuer, iat, nonce required when nonce endpoint exists, iss omitted for anonymous pre-auth); F.3 attestation proof; F.4 proof verification list.
- RFC 9449 DPoP: 4.2 syntax, 4.3 the 12 checks (typ dpop+jwt, asymmetric alg only, no private key in jwk, htm, htu, iat window, jti replay, ath, key bound to token), 5 token_type DPoP, 7.1 Authorization: DPoP scheme, 7.2 reject DPoP-bound token sent as Bearer, 8/9 nonces.
- HAIP 1.0 Final: 4 (authorization code flow MUST, PKCE S256, PAR when using authorization endpoint, DPoP MUST, batch metadata), 4.1 (scope for every config, nonce_endpoint when key binding, signed metadata), 4.4.1 wallet attestation (OAuth client attestation at PAR + token endpoint, x5c), 4.5.1 key attestation (x5c, signing cert not self-signed), 6.1 SD-JWT VC (exp and/or status, cnf.jwk, status_list, unique unpredictable status index), 6.1.1 x5c issuer chain without trust anchor, 7 ES256 minimum.
- Token Status List draft-ietf-oauth-status-list-21: 4.1 bits 1/2/4/8, ZLIB/DEFLATE; 5.1 typ statuslist+jwt, sub = uri, iat, exp, ttl; 6.2 status.status_list.idx/uri; 7.1 0x00 VALID, 0x01 INVALID, 0x02 SUSPENDED; 8.2 media type application/statuslist+jwt; 12.5.1 random indices, decoys; 13.2 fresh entry per (batch) token; 13.3 no double allocation.
- SD-JWT VC draft-23: typ dc+sd-jwt; vct required; iss/nbf/exp/cnf/vct/status never selectively disclosable; cnf required with key binding.
- ISO/IEC 18013-5 mdoc: MSO, COSE_Sign1 (ES256 / -7), x5chain, validityInfo, deviceKeyInfo, digest per element.
